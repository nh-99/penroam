# BOOX device run — 2026-11-02 (Note Air5 C, Android 15, 38 Hz colour EPD)

Device inventory: `device.md`. Raw exports: `native/`, `flutter/perf/`, `tauri/perf/`.
All three apps use the same `android/boox-ink` module, Mode B (Onyx `TouchHelper` raw
drawing), handoff `PEN_UP_REFRESH`, rawRender ON, `create(view, cb)`.

## User observations (by eye, same user, same session)

| App | Ink under the pen | After pen-up |
|---|---|---|
| Native reference | instant, "felt good, no lag" | stayed exactly put, no visible change |
| Flutter (Platform View, hybrid composition) | instant, "very minimal lag" | stayed put |
| Tauri (Kotlin overlay above WebView) | instant, "very minimal lag" | stayed put |
| Tauri Mode A (HTML canvas; Mode B was blocked by a bug, see below) | "slight input delay" | n/a |

## Measured (callback-level; not pen-to-photon)

| | Native | Flutter | Tauri |
|---|---:|---:|---:|
| strokes / samples | 5 / 1,973 | 39 / 10,648 | 89 / 11,258 |
| sample interval median / max ms | 2 / 4 | 2 / 9 | 2 / ≤6 |
| gaps / spatial jumps | 0 / 0 | 0 / 0 | 0 / 0 |
| Onyx input → callback ms, median / p95 / max | 0 / 1 / 7 | 0 / 12 / 66 | 0 / 12 / 30 |
| MotionEvent → handler ms, median / p95 / max | 6 / 7 / 13 | 7 / 24 / 136 | 6 / 9 / 83 |
| pen-up → persistent ink rendered ms, median / p95 | 148 / 154 | 145 / 162 | 142 / 157 |
| pen-up refresh callback arrived (else 120 ms fallback) | 2 / 5 | 15 / 39 | 18 / 89 |
| raw drawing open ms | 51 | 45 | 45 |
| first frame on launch (ActivityTaskManager "Displayed") | 373 ms (cold) | 1,280 ms cold / 704 ms warm | 411 ms |
| app process RSS | – | 225 MB | 350 MB (+ WebView renderer process, not counted) |

* The hardware preview (the ink the user sees while writing) is drawn by the EPD controller,
  so none of the callback numbers above is the visible latency. By eye, all three were
  equally immediate in Mode B.
* The pen-up figure is dominated by the 120 ms fallback timer: Onyx's pen-up refresh callback
  arrives for only about 20–40% of strokes on this firmware. That is a tuning target for
  every host (try `TOGGLE_RAW` / `REGIONAL_GC`, or a shorter fallback), not a framework
  difference.
* Both framework hosts show heavier tails in callback delivery than the bare native app
  (p95 12 ms vs 1 ms), as expected with a framework engine sharing the process.
* Mode A in Tauri (web canvas only, 16 strokes): event → handler 33 / 37 ms, event → render
  36 / 41 ms, frame 26.4 ms (38 Hz). This is what drawing costs without the native driver.

## Defects found and fixed during the run

1. **Android 15 edge-to-edge:** the native reference app's toolbar sat under the status bar,
   so taps on it were swallowed. Fixed with system-bar insets. Flutter (`SafeArea`) and Tauri
   (CSS `env(safe-area-inset-*)`, honoured by WebView 146) were already correct.
2. **Tauri ACL:** `plugin:boox-ink|registerListener not allowed by ACL`. Plugin events need
   the `registerListener` / `remove_listener` commands allowed. The app silently stayed in
   Mode A, and the status line showed the error. Fixed in both plugins (BOOX and PencilKit).
3. **BOOX auto-freeze** disables freshly installed apps (`enabled=3`). Use
   `adb shell pm enable <pkg>`, or exclude the apps in BOOX settings.
4. Flutter and Tauri perf exports went to app-private storage, which cannot be pulled on
   release builds. Both now write to `/sdcard/Android/data/<id>/files/perf` like the native app.
