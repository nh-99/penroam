## 2. Decisions (ADR-003 draft — needs owner sign-off, recorded in results)

1. **Keep `.prp` v1.** No new codec. v1 gains a forward-compatibility rule: header flag bits 0–7 are *required* features (unknown → refuse), bits 8–15 *optional* (unknown → ignore). Flag bit 8 announces an *extension area* of tagged records after the point blocks; record tags carry `required` and `copy-safe` bits. Unknown required → refuse; unknown optional copy-safe → preserved verbatim on re-save; unknown optional not-copy-safe → page opens **read-only** (never stripped). The current encoder emits none, so its output is byte-identical to M01.
2. **Separate versions.** `binary::FILE_FORMAT_VERSION` (= 1, `.prp`), `journal` format (= 1), archive `FORMAT_VERSION` (= 2), `NOTEBOOK_SCHEMA_VERSION` (= **2**), `PAGE_SCHEMA_VERSION` (= 1), `OP_SCHEMA_VERSION` (= 1). None derived from another.
3. **Notebook schema v1 → v2**: adds `orderKeys` (fractional page order keys, the convergent ordering the protocol requires). Migration is additive and deterministic. Bumping is also the only lever that makes **M01 builds fail safely** on an M02 library: M01 refuses `schemaVersion > 1` and leaves the notebook untouched instead of reading pages while ignoring the new journal. Downgrade to M01 is therefore unsupported (documented).
4. **Operation algebra in `penroam-core::operation`**: `LocalOperation {id, device_id, local_sequence, schema_version, causal_dependencies, at, body}` with `DocumentOperation` variants for exactly the M01 features (notebook create/rename/cover/trash/restore/purge, page create/trash/restore/reorder/template, element add/remove/replace, asset reference). Page element ops reuse the M01 `PageOperation` op ids, so local replay is bit-identical to `apply_batch`. Merge semantics live in a pure `Replica`: multi-value registers with version-vector dominance (no timestamps), deterministic winner + retained alternates, tombstones, explicit restore, add-wins restore, delete-vs-concurrent-edit conflict, fractional page keys with id tie-break, idempotent dedup by op id, op-id reuse rejected, unknown schema refused (`upgrade_required`), causal gaps reported.
5. **Journal**: one device-wide, segmented, append-only binary op log `<library>/journal/` (record = one atomic transaction of ops, magic + length + CRC-32 + payload; ink points in the `.prp` column encoding). fsync before `Saved locally`. Checkpoint manifest (`checkpoint.json` + previous copy) persisted atomically; page snapshots keep one fallback generation (`.prp.prev`) and segments are only deleted once *both* the current and the previous checkpoint cover them. Torn tail truncated, mid-log corruption reported and preserved (no truncation, later records quarantined, appends move to a new segment). Exclusive library lock (`File::try_lock`). Append failure (e.g. ENOSPC) truncates back to the last good record.
6. **Outbox index**: small atomic file (`outbox.json`, counters `enqueued`, `uploaded`, `remote_seen` + device id) derivable from the journal; corrupt/missing → rebuilt with `uploaded = 0` (re-upload is safe because the server dedups by op id), never loses ops. Retention honours `uploaded` only when sync is enabled (M03). SQLite was not added: a second store would need its own crash story for three counters.
7. **Migration of M01 libraries**: per notebook, back up `notebook.json`, legacy `*.journal`, legacy `*.json` pages and affected `.prp` into `<library>/migration-backups/<ts>-m01/`, fold legacy journals into new `.prp` snapshots, write `notebook.json` v2 (commit point), then remove legacy files. Idempotent if interrupted at any step.
8. **Sync crates** `penroam-sync-protocol` (DTOs, canonical bytes, framing, limits, error codes, negotiation) and `penroam-sync-testkit` (in-memory fake server, fixture generator + `--check`), no dependency on core/storage/Tauri.

## 4. Risks

* Journal rewrite touches the only durability path → every boundary is fault-injected; M01 crash tests kept.
* Notebook schema bump blocks M01 downgrade (intended, documented).
* Equal-z element ordering is insertion-order dependent locally; the `Replica` orders by `(z, id)` for convergence. Local replay keeps M01 semantics exactly.
* Not in M02: networking, accounts, encryption, OCR; no UI beyond keeping "Saved" truthful.
